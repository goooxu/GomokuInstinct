# gomoku-instinct

从零自博弈训练的连珠（五子棋）AI。**对战时不使用任何搜索** —— 落子完全由一次网络前向 + argmax 决定。

> 想了解它是怎么做出来的？看 **[技术报告](docs/)** —— 12 章，面向会用 PyTorch、
> 但没有强化学习背景的读者，含踩过的坑与一个否定性结论。

## 项目约束

这个项目刻意给自己设了几条硬约束：

- **零棋谱**：全部知识来自游戏规则本身，训练与测试数据都由自博弈产生，不接触任何人类对局记录。
- **零搜索推理**：对战时没有 MCTS、没有 rollout、没有开局库。网络看一眼棋盘就落子。
- **自研结构**：网络结构自行设计，不复用任何开源五子棋 AI 的模型结构。
- **零预训练权重**：全部从随机初始化开始。
- **BF16 主权重**：模型主权重本身就是 BF16（不是 FP32 master + BF16 autocast），配合混合精度训练。

其中「零搜索推理」是整个项目的技术主线。AlphaZero 类方法的棋力一半来自网络、一半来自树搜索；把搜索从推理端拿掉后，原始策略网络通常远弱于它自己的 MCTS 版本。本项目要做的事情，就是把搜索能力尽可能完整地压进权重里。

## 棋规

15×15 标准连珠禁手，自由开局：

- 白方无禁手，五连及以上（含长连）即胜。
- 黑方**恰好**五连才胜；长连（≥6）、四四、三三均为禁手。
- 禁手点仍在动作空间内，黑方落上去**立即判负**（严格 RIF 语义）。
- 黑方同时成五与禁手时，五连优先，判黑胜。

因此避开禁手是模型必须自己学会的能力，而不是由引擎代劳 —— 对战工具默认**不**为 AI 屏蔽禁手点。

## 快速开始

所有编译与运行都在容器内进行：

```bash
# 进入容器（工作目录在容器内保持同一路径）
./scripts/docker_run.sh

# 环境自检：GPU 可见性、BF16 matmul、C++ 工具链
python scripts/check_env.py

# 运行测试
pytest tests/
```

## 训练

多卡编排：一张卡跑 trainer，其余卡各跑一个自博弈 actor。

```bash
./scripts/launch_training.sh runs/renju15c          # 启动（已有进度则自动续训）
python scripts/report.py --run-dir runs/renju15c    # 看进展
python scripts/report.py --run-dir runs/renju15c --arena 200   # 顺带跑一轮竞技场
./scripts/launch_training.sh runs/renju15c stop     # 停止
```

actor 与 trainer 之间只通过文件系统交互：actor 定期热加载 `checkpoints/latest`，
把样本写成分片；trainer 扫描新分片并训练。分片与 checkpoint 都是原子写入，
因此任一侧崩掉或整机被抢占，重启后都能从磁盘上的最新状态原地接上。

单卡跑通全链路（用于快速验证）：

```bash
python scripts/train.py --run-dir runs/dev9 --board-size 9 \
    --override num_games=512 sims=96 batch_size=512 min_positions_to_start=3000
```

## 人机对战

```bash
gomoku-instinct serve --ckpt <checkpoint> --port 8000

# --ckpt 可以给多次，页面上就能切换；第一个是初始模型
gomoku-instinct serve --ckpt runs/renju15c --port 8000

# 训练还在跑时加这个，每 60 秒自动换上最新 checkpoint，页面顶部的 step 会跟着走
gomoku-instinct serve --ckpt runs/renju15c --reload-seconds 60
```

然后浏览器打开 `http://localhost:8000/`。棋盘是画出来的真棋盘：鼠标悬停会在落点上
显示半透明的棋子、四边坐标同步高亮，确认了再点。执黑时禁手点标红 ×。
方向键 + 回车也能落子。窗口变窄时会自动从左右排布改成上下排布，
判据是"哪种排法棋盘更大"。

AI 每落一手，那颗子上会写出模型给这一手的概率，同时用蓝圈标出它当时**另外**在考虑的
点及概率 —— 概率不低于阈值的全部标出来，阈值在页面上可调（默认 5%），
看得见它有多犹豫。右侧另有 AI 自评、候选手列表、可点击回看的棋谱。

**用哪个模型是每局各自的事**：开两个标签页就是两局，可以分别选不同的模型同时下，
拿同一个局面直接对比。刷新不会丢棋。

服务端只用标准库的 `http.server`，没有额外依赖。**默认只监听回环地址** —— 页面没有
任何认证，开发机通常是共享的。要从自己的机器访问，用 SSH 端口转发：

```bash
ssh -L 8000:127.0.0.1:8000 <开发机>     # 然后本地浏览器打开 http://localhost:8000/
```

`--host 0.0.0.0` 可以直接对同网段开放，风险自负。

## 设计要点

**网络 `InstinctNet`（自研）** —— 走「深而窄」，用网络深度替代搜索深度。主干由 Directional Line Block 堆叠而成：每个 block 一路做四方向（横/竖/双对角）的长核 depthwise 1-D 卷积，把「五子棋的一切都发生在直线上」这个结构先验直接写进架构；另一路做 3×3 局部形状卷积；再经 1×1 混合与全局门控。每隔若干 block 插入一层**全盘自注意力**——15×15 只有 225 个位置，全局注意力的开销与一个卷积块相当，用来建模跨越棋盘的威胁组合（四三、双三这类需要两处威胁互相支援的推理）。

输入平面只有棋子分布、行棋方、最近数手等规则直接导出的信息，**刻意不喂手工战术特征**；活三/冲四之类的棋型改为辅助监督目标，逼网络自己长出威胁识别能力。

**辅助监督头** —— 除策略与价值外，还预测：逐点棋型、黑方禁手点、剩余手数、对手应手分布。这些标签全部由规则导出，用来把本该由树展开得到的信息直接灌进网络。

**BF16 主权重** —— BF16 只有 7 位存储尾数（含隐含位共 8 位有效位），朴素的 `w += lr*g` 在更新量小于半个 ULP 时会被完整舍掉，训练中期彻底停滞。优化器采用 Kahan 补偿求和保留被舍掉的低位（另提供随机舍入作为对照）；Adam 一/二阶矩保持 FP32。

**训练/部署分布对齐** —— 一部分自博弈对局由零搜索策略执行落子，但训练目标仍由 MCTS 生成；同时定向挖掘「零搜索会走错且错得厉害」的局面加权重训（信号取搜索最优手与零搜索选点的 Q 差）。模型晋级评测一律在零搜索模式下进行，且每局随机开局若干子——两个确定性 player 对弈时不这么做，每局都是同一盘棋的重放，胜负只由先后手决定。

## 当前状态

当前模型练了 48,000 步（`runs/renju15c`）。零搜索策略（单次前向 + argmax）的实测棋力，
各 200 局、随机开局 2 子：

| 对手 | 结果 |
|---|---|
| 随机落子 | **200胜 0负**（得分率 100%，Elo +1040），0 次禁手告负 |
| 规则基线（贪心威胁） | **199胜 1负**（得分率 99.5%，Elo +920） |
| 同权重 MCTS | 约相当于**不到 2 次模拟**的搜索强度 |

前两项已接近饱和，没有分辨力了；最后一项是本项目的头号指标，也是**尚未解决的核心
问题**：AlphaZero 类方法的棋力一半来自搜索，把搜索从推理端拿掉后要靠权重补回来。
目前几乎没有压缩进去。

已经确认的一件事是：**这个差距不能靠「把访问分布拟合得更准」来缩小**。这一轮的
训练侧指标全面优于此前任何一轮（策略损失相对目标熵的超出量 0.391，全项目最低），
绝对棋力也确实更强，而搜索差距纹丝不动。

关键在于**这个指标是相对的**：分母是模型自己的 MCTS，网络变强教师同样变强 ——
训练让学生和老师一起进步，却没有缩短两者的距离，而部署时只有学生。
完整论证见[技术报告第 12 章](docs/12-negative-result.md)。
