# gomoku-instinct

从零自博弈训练的连珠（五子棋）AI。**对战时不使用任何搜索** —— 落子完全由一次网络前向 + argmax 决定。

## 项目约束

这个项目刻意给自己设了几条硬约束：

- **零棋谱**：全部知识来自游戏规则本身，训练与测试数据都由自博弈产生，不接触任何人类对局记录。
- **零搜索推理**：对战时没有 MCTS、没有 rollout、没有开局库。网络看一眼棋盘就落子。
- **自研结构**：网络结构自行设计，不复用任何开源五子棋 AI 的模型结构。
- **零预训练权重**：全部从随机初始化开始。
- **BF16 主权重**：模型主权重本身就是 BF16（不是 FP32 master + BF16 autocast），配合混合精度训练。

其中「零搜索推理」是整个项目的技术主线。AlphaZero 类方法的棋力一半来自网络、一半来自树搜索；把搜索从推理端拿掉后，原始策略网络通常远弱于它自己的 MCTS 版本。本项目要做的事情，就是把搜索能力尽可能完整地压进权重里。

## 棋规

15×15 标准连珠禁手，自由开局：

- 白方无禁手，五连及以上（含长连）即胜。
- 黑方**恰好**五连才胜；长连（≥6）、四四、三三均为禁手。
- 禁手点仍在动作空间内，黑方落上去**立即判负**（严格 RIF 语义）。
- 黑方同时成五与禁手时，五连优先，判黑胜。

因此避开禁手是模型必须自己学会的能力，而不是由引擎代劳 —— 对战工具默认**不**为 AI 屏蔽禁手点。

## 快速开始

所有编译与运行都在容器内进行：

```bash
# 进入容器（工作目录在容器内保持同一路径）
./scripts/docker_run.sh

# 环境自检：GPU 可见性、BF16 matmul、C++ 工具链
python scripts/check_env.py

# 运行测试
pytest tests/
```

## 人机对战

```bash
gomoku-instinct play --color black --ckpt <checkpoint>
```

对局中可用命令：`undo` / `hint` / `save` / `load` / `resign` / `quit`。

常用选项：

| 选项 | 说明 |
|---|---|
| `--color black\|white` | 人类执子颜色 |
| `--show-policy` | 显示 AI 的 top-5 候选手概率、value 估计与禁手点预测 |
| `--safe-mode` | 用规则给 AI 兜底屏蔽禁手点。**默认关闭** —— 开启后落子就不再是纯模型推理了 |

## 结构

```
configs/           规则、模型、训练配置
csrc/              C++ 核心：位棋盘、禁手判定、棋型标注、MCTS、向量化自博弈
gomoku_instinct/
  rules/           规则的 Python 参考实现（仅用于差分测试）
  model/           InstinctNet 网络结构
  optim/           BF16 主权重优化器（Kahan 补偿求和）
  selfplay/        自博弈 actor 与批量推理
  train/           trainer、replay buffer、损失
  eval/            竞技场、Elo、规则基线对手
  cli/             命令行入口与人机对战
scripts/           容器启动、训练/自博弈启动、环境自检
tests/             规则差分测试、优化器数值测试等
```

## 设计要点

**网络 `InstinctNet`（自研）** —— 走「深而窄」，用网络深度替代搜索深度。主干由 Directional Line Block 堆叠而成：每个 block 一路做四方向（横/竖/双对角）的长核 depthwise 1-D 卷积，把「五子棋的一切都发生在直线上」这个结构先验直接写进架构；另一路做 3×3 局部形状卷积；再经 1×1 混合与全局门控。每隔若干 block 插入轴向注意力，用来建模跨越棋盘的威胁组合（四三、双三这类需要两处威胁互相支援的推理）。

输入平面只有棋子分布、行棋方、最近数手等规则直接导出的信息，**刻意不喂手工战术特征**；活三/冲四之类的棋型改为辅助监督目标，逼网络自己长出威胁识别能力。

**辅助监督头** —— 除策略与价值外，还预测：逐点棋型、黑方禁手点、剩余手数、对手应手分布。这些标签全部由规则导出，用来把本该由树展开得到的信息直接灌进网络。

**BF16 主权重** —— BF16 只有 8 位尾数，朴素的 `w += lr*g` 在训练中期会因舍入而彻底停滞。优化器采用 Kahan 补偿求和保留被舍掉的低位（另提供随机舍入作为对照）；Adam 一/二阶矩保持 FP32。

**训练/部署分布对齐** —— 一部分自博弈对局由零搜索策略执行落子，但训练目标仍由 MCTS 生成；同时定向挖掘「原始策略与 MCTS 分歧大」的局面加权重训。模型晋级评测一律在零搜索模式下进行。
