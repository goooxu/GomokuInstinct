# 导读

## 这份报告写给谁

假定你：

- 写过 PyTorch 的训练循环 —— 知道 `loss.backward()`、`optimizer.step()`、`nn.Module`；
- 知道卷积和注意力大致在做什么；
- **没有**强化学习背景，没听说过（或只模糊听说过）AlphaZero、MCTS、PUCT；
- **不会下五子棋**也没关系，规则在第 1、2 章讲清楚。

不假定你熟悉 C++。项目里有 2300 行 C++，但报告会把它当作"一个提供了这些函数的黑盒"
来讲，只在讲到"为什么必须用 C++"时展开实现。

## 一个提前打的预防针

强化学习的教程通常长这样：讲清算法 → 给出伪代码 → 结果很好。

这份报告不是那样。它有相当篇幅在讲**没做成的事**和**不报错的 bug**：

- 第 11 章列了二十个 bug，它们的共同点是**测试不会变红、程序不会崩、日志里什么都没有**，
  只是训练悄悄停在原地或者结果悄悄变差；
- 第 12 章是一个否定性结论：训练侧的所有指标都在变好，而真正关心的那个指标一动不动。

之所以把这些写进来，是因为这两类内容恰恰是教程里最缺、而实际做项目时占时间最多的部分。
如果你只想看"正确做法"，可以跳过第 11、12 章；但我建议至少读第 11 章开头那段方法论。

## 怎么对照代码读

仓库结构（完整版见 [`../README.md`](../README.md) 的「结构」一节）：

```
csrc/                  C++ 核心：规则判定、MCTS、向量化自博弈
gomoku_instinct/
  rules/               规则的 Python 参考实现（只用于差分测试）
  model/               网络结构与特征编码
  optim/               BF16 主权重优化器
  selfplay/            把 C++ runner 和 GPU 网络接起来
  train/               回放池、损失、训练循环
  eval/                竞技场、Elo、规则基线对手
  cli/ web/            零搜索对战引擎与网页版界面
scripts/               容器、训练编排、评测、基准
tests/                 200 个测试函数（参数化展开后用例更多）
```

每章末尾有一张**代码索引**表，列出该章讲到的文件与符号。这张表被
[`tests/test_docs.py`](../tests/test_docs.py) 自动校验：如果代码里改了类名而文档没跟着改，
测试会红。所以表里的名字可以放心当作真的。

报告里**不写行号** —— 行号是最容易腐烂的引用。要定位符号请用编辑器的搜索。

## 项目是怎么一步步长出来的

主体在约一天的墙钟时间里完成，按里程碑推进。这个顺序不是事后整理的，
而是实际的开发顺序，本身包含一个判断：**先把"错了就全错"的东西钉死，再往上盖。**

| 里程碑 | 做了什么 | 为什么排在这个位置 |
|---|---|---|
| **M0** | 仓库骨架、容器环境、环境自检 | 自检顺带实证了 BF16 朴素累加会完全停滞，为 M2 的方案定了调 |
| **M1** | 连珠规则引擎：C++ 实现 + Python 参考实现 + 差分测试 | 规则错了，后面所有训练信号都是错的，而且不会报错。设了硬性验收门槛，不通过不往下走 |
| **M2** | InstinctNet 网络 + BF16 主权重优化器 | 有了规则才能定义输入平面和辅助标签 |
| **M3** | MCTS + 向量化自博弈 runner | 有了网络才有东西可以被搜索调用 |
| **M4** | 训练循环、回放池、完整续训 | 有了数据来源才谈得上训练 |
| **M5** | 9×9 小棋盘端到端验证 | **在小棋盘上先证明整条链路真的能学**，再上 15×15 烧机器 |
| **M6** | 15×15 正式训练、多卡编排 | |
| **M7** | 零搜索专项优化、网页版对战 | |

M5 那一步值得单独说：9×9 的一轮完整验证只要几十分钟，而 15×15 要按天算。
**用小规模先跑通全链路**，把"数据格式对不对、损失下不下降、续训接不接得上"这类问题
在便宜的地方暴露掉，是这个项目里性价比最高的一个决定。

里程碑之后还有一批工作，它们贡献了报告里分量最重的几个结论：

| 之后做的 | 结论落在哪 |
|---|---|
| 一次学习率衰减实验 | 第 12 章的否定性结论 |
| 换采样方式：只训练每局最后 20 手（尾段重搜） | 第 12 章；绝对棋力提升，但不在核心命题上 |
| 把它跑满 5 万步并做完整评测 | [附录 B](appendix-renju15f.md) |
| 网页版观战（两个模型互下）与随机开局 | 第 9、10 章 |
| 发现**头号指标不能横向比较两个模型** | 第 9 章、第 12 章 §12.8 |
| 发现**开局盲区**并打补丁 | 第 10 章、第 12 章 §12.8、附录 B |

最后两项是回头看最有价值的部分：**它们都不是"模型不够强"，
而是"我们量错了东西"。**

## 一些数字，方便你有个尺度感

以主线模型 `renju15f` 为准（[附录 B](appendix-renju15f.md)）：

| | |
|---|---|
| 代码量 | Python 约 10,700 行（含 3,700 行测试，200 个测试函数），C++ 约 2,500 行 |
| 模型 | 4.44M 参数，20 层 × 128 通道 |
| 训练 | 50,000 步，trainer 端墙钟约 24 小时，中途被外部中断 4 次、每次原地续训 |
| 自博弈产出 | 1,280 万个训练局面 |
| 硬件 | 4 张 GPU：1 张跑训练，3 张跑自博弈 |
| 落子耗时 | 约 11 毫秒（单次前向，无搜索） |
