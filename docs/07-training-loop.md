# 第 7 章　训练循环

数据有了（第 6 章），网络有了（第 4 章），优化器有了（第 5 章）。这一章把它们接起来。

## 7.1 回放池：为什么不边下边训

最直接的做法是：下完一批棋，立刻拿来训一遍，扔掉，再下一批。

不行，两个原因。**其一**，相邻局面高度相关 —— 同一局棋里连续两手的棋盘只差一颗子，
用它们组成的 batch 做梯度估计，方差极大。**其二**，自博弈很贵。花大力气产生的样本
只用一次太浪费。

于是用**回放池**（replay buffer）：一个容量 400 万局面的滑动窗口，新数据进来、
最旧的出去，训练时从中**随机采样**。随机采样打破了相关性，滑动窗口保证数据不会太旧
（太旧的样本来自弱得多的网络，学它没意义）。

回放池同时负责落盘：每攒够 65,536 条就写一个分片文件，最多保留 400 个。
第 8 章会讲这些分片同时也是 actor 与 trainer 之间的通信媒介。

## 7.2 一个会自己跑偏的配比

"自博弈跑 200 步，然后训练跑 N 步"，N 该取多少？

第一版写死了一个常数。M5 的小棋盘验证里抓到问题：**样本复用比飙到了 23.8** ——
每条样本平均被训练啃了将近 24 次。这意味着自博弈根本跟不上，网络在反复过拟合一小撮
旧数据。

而这件事**从 loss 曲线上完全看不出来**：loss 在降，降得还挺好看 —— 它在越来越好地
拟合那一小撮数据。

改法是让训练步数**自适应**：每个周期实测当前的复用比，往目标值 4.0 上追，
上限 400 步。

```python
reuse = samples_seen / buffer.total_added        # 实际复用比
steps = clamp(target_reuse * total_added - samples_seen, ..., max_steps_per_cycle)
```

教训是通用的：**任何"两个组件按固定配比协作"的设计，都要问一句"如果一边变慢了会怎样"。**
答案通常是"另一边悄悄空转或者悄悄过拟合"，而且不报错。

顺带一提，`buffer/reuse` 这个指标被记进了日志，就是为了让这件事以后能被看见 ——
又一个第 5 章说的"给静默失败装一个指针"。

## 7.3 六项损失

```
总损失 = 1.0 × 策略
       + 1.0 × 价值
       + 2.0 × 禁手质量惩罚          ← 不随辅助头衰减
       + 1.0 × 禁手边际损失          ← 不随辅助头衰减
       + aux_scale × ( 0.3 × 威胁 + 0.6 × 禁手点 + 0.1 × 剩余手数 + 0.2 × 对手应手 )
```

**策略损失**是与 MCTS 访问分布的交叉熵。**价值损失**是胜/和/负三分类的交叉熵。
这两项是主干。

**四个辅助头**的标签全部由规则免费导出。它们的作用是给网络提供密集的学习信号 ——
策略和价值每个局面各只有一个标签，而威胁头每个局面有 225 × 2 个标签。
早期训练时这些信号能大幅加速收敛。

`aux_scale` 从第 20 万步开始线性衰减，到第 40 万步降到 0.1。理由是辅助任务是**脚手架**：
早期帮网络建立表示，后期继续用力反而会挤占容量去做一件部署时用不上的事。

**两个禁手相关的损失项不随 aux_scale 衰减**，因为它们不是脚手架，是硬约束。下一节细说。

## 7.4 为了压住禁手，加了两个损失项

这是一段有意思的排查过程。

**第一阶段：策略变强之后，禁手告负率反而涨了。** 从 0.17% 一路涨到 **6%**。

原因不难理解：随着黑方越下越凶，它最想走的那些"最强手"恰恰经常是三三、四四 ——
禁手规则限制的正是最有威力的棋型。策略越强，越往禁手上撞。

MCTS 的目标分布里禁手点概率确实接近 0（第 6 章），但那点概率质量分散在 225 个点里
微不足道，**交叉熵推不动它**。于是加了第一个专项损失：

> **禁手质量惩罚**（权重 2.0）：直接惩罚策略分布落在禁手点上的**总概率质量**。

**第二阶段：质量惩罚生效了，但没解决问题。** 无条件的"禁手点 argmax 率"被压到 0.4%
以下，可自博弈里的禁手告负率仍有 **3.6%**。

再查才明白：质量惩罚压的是**整体分布**，而零搜索部署时真正致命的是 **argmax 落错**。
更要命的是那 0.4% 的统计口径 —— 它把**根本不存在禁手点的局面**也算进了分母。
绝大多数局面没有禁手点，自然不会犯错，把真正危险的那批局面稀释得看不见了。

于是加了第二个损失项，并且**只在危险局面上施压**：

> **禁手边际损失**（权重 1.0，余量 2.0）：在"轮到黑方、且盘上确实存在禁手点、
> 且存在安全着法"的样本上，要求最优安全着法的 logit 比最高禁手点的 logit
> 至少高出 2.0。

同时把指标改成**有条件的**：`policy/forbidden_argmax_rate_risky` ——
只在危险局面上统计。这个数才是真的。

最终禁手告负率被压到 0.09%~0.52%。

这段经历的通用教训：**指标的分母决定了它能不能骗你。** 第 9 章整章在讲这件事。

## 7.5 策略损失里的一个 NaN 陷阱

策略损失要在合法点上算交叉熵，所以非法点的 logit 先被设成 `-inf`：

```python
logp = logits.masked_fill(~legal, float("-inf")).log_softmax(-1)
loss = -(target * logp).sum(-1)      # ← 这里会出 NaN
```

问题在于非法点的 `target` 是 `0`，而 `logp` 是 `-inf`：

```
0 × (-inf) = NaN
```

一个 NaN 会顺着反向传播污染整个梯度，所有权重一步变 NaN。表现出来是 loss 突然变
`nan` 然后再也不动 —— 而根因在一个看起来完全无害的乘法上。

修法：

```python
logp = torch.where(legal, logp, torch.zeros_like(logp))
```

非法点的 `target` 本来就是 0，把 `logp` 换成任何有限值都不影响结果，只要不是 `inf`。

## 7.6 八重对称：一个局面变八个

第 2 章那套用来做规则不变性检查的对称变换，在这里被复用成**数据增强**：
采样时随机选一种变换（4 个旋转 × 2 个镜像），把整个样本变过去。

关键是**哪些字段要跟着变**：

| 字段 | 怎么处理 |
|---|---|
| `boards`、`policy`、`threat_*`、`forbidden` | **按格重排**（每个格子搬到新位置） |
| `history`、`next_move` | 是**落点下标**，用变换表正向映射；`-1` 保持不变 |
| `value`、`plies_remaining`、`to_move` | 不变（对称不改变胜负和手数） |

漏掉任何一个字段都会产生"棋盘转了但标签没转"的样本，而这种脏数据**不会报错**，
只会让训练变慢、上限变低。测试里对每个字段逐一验证了变换的自洽性。

## 7.7 辅助标签算在入库时，不算在训练时

威胁标签和禁手点标签要调规则引擎算，`225 × 2` 个点全扫一遍。这活儿不便宜。

如果放在训练循环里算，每个 batch 都要重算一次 —— 而同一条样本会被复用 4 次，
等于白算 3 次，还占着 GPU 等 CPU。

所以标签在**样本入库时**算一次，存进回放池。`ThreadPoolExecutor` 摊到多核，
C++ 侧在计算时释放 GIL，所以是真并行。

## 7.8 失误挖掘

第 1 章提到的第四个手段。自博弈时，对每个样本额外记一个数：

```
blunder_gap = 搜索最优手的价值 − 零搜索会选的那一手的价值
```

这个差值大，说明**零搜索策略在这个局面上会走错，而且错得厉害**。这正是最该重训的样本。

采样时定向过采样：批次里最多 20% 来自 `blunder_gap > 0.15` 的样本池。

实现上有个细节值得一提：C++ 侧的 `root_child_values()` 对**未访问过的着法写 -1**，
即按最坏情况算。这是保守的选择 —— 宁可低估一个着法的价值，也不要因为它没被搜索访问过
就误以为它很好，从而虚报一个不存在的失误。

## 7.9 学习率

`warmup 2000 步` → `cosine 衰减到峰值的 5%`，峰值 `2e-3`。

warmup 是必要的：BF16 主权重 + 20 层深网络，一开始就上大学习率很容易废掉。
第 4 章那个"每个块初始为恒等映射"的零初始化也是同一个目的。

第 12 章会讲一次专门的学习率实验，以及它得出的那个否定性结论。

## 7.10 一步训练长什么样

```python
lr = lr_at(step)                                  # warmup + cosine
batch = buffer.sample(batch_size)                 # 随机采样 + 对称增强 + 失误过采样
planes = encode(batch.boards, ...)                # (1024, 10, 15, 15) bfloat16
out = forward(planes)                             # torch.compile 过的模型
loss, metrics = compute_losses(out, batch, weights, step)
loss.backward()
clip_grad_norm_fp32(params, 1.0)                  # 范数在 FP32 下算
optimizer.step()                                  # BF16 权重 + Kahan 补偿
optimizer.zero_grad(set_to_none=True)
```

和任何一个 PyTorch 训练循环长得一样。区别全在被调用的那几个函数里面。
