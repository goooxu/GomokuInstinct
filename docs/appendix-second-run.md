# 附录 B　第二次训练：renju15b @ step 10,001

[附录 A](appendix-training-run.md) 记的是唯一一次 30,000 步训练（`renju15`）。
这一份记的是**用同一套方案、在另一台机器上从随机初始化重跑的第二次训练**，
只把训练步数收到 10,000。

它的价值不在于练出了更强的模型（没有，它明显更弱），而在于**同一套方案跑两次**
能回答一些一次训练回答不了的问题：哪些现象是方案的性质，哪些只是那一次的偶然。

> **这一轮的产物已全部删除。** `runs/renju15b` 整个目录（权重、训练曲线、自博弈日志、
> 头号指标记录）在第三轮训练期间被清理掉了。本附录里的每一个数字都是删除前记下的，
> **无法再复算，也无法重测**。
>
> 这是一个有意识的取舍：这一轮的结论已经写进正文，而模型本身比 renju15 弱、
> 没有保留价值。但要清楚代价 —— 附录 A.1 记过同一件事（renju15 的分片被清理后，
> 训练起止时刻永久查不回来），`wall_time` 就是为此加的；这次连 `metrics.jsonl`
> 本身都没了，补救措施也一并失效。**留下的只有这份文档。**

## B.1 和第一次的差别

只有两处：

| 项 | renju15 | renju15b |
|---|---|---|
| `max_steps` | 30,000 | **10,000** |
| `metrics.jsonl` | 不记墙钟时间 | **每条记录带 `wall_time`** |

其余全部相同：InstinctNet 20×128（4.44M 参数）、BF16 主权重 + Kahan、
batch 1024、峰值学习率 2e-3、warmup 2,000 步、余弦衰减到 1e-4、
回放池 400 万、目标样本复用率 4.0、sims 400 / fast 100、完整搜索比例 0.25、
Dirichlet α=0.15 ε=0.25、前 16 手温度 1.0、部署分布自博弈 25%、认输关闭、
4 卡（1 trainer + 3 actor）。

**`max_steps` 不只是"跑到哪停"**：学习率的余弦衰减以它为分母。所以这两次训练
不是"同一条曲线截在不同位置"，而是**两条完整走完的曲线**，只是一条压缩在 10,000 步内。

（`configs/train_4gpu.yaml` 里那个值会随每轮训练改动，别拿它反推历史。
每一轮实际用的配置随 `trainer_cfg` 存在各自的 checkpoint 里，事后可查。）

`wall_time` 那条是附录 A.1 里自己记下的疏漏 —— 第一次训练没记墙钟时间，
等自博弈分片被清理后，"训练到底跑了多久"就永久查不回来了。这次补上，
而且它很快就派上了意料之外的用场（第 11 章 #16）。

## B.2 规模与产出

| | |
|---|---|
| 训练步数 | **10,001** |
| trainer 墙钟 | **15,474 秒 = 4.30 小时**（一次跑完，中途没有中断） |
| 平均每步 | 1.547 秒 |
| 喂进训练的局面 | **2,560,345**（末态回放池，**没有填满** 400 万上限） |
| 样本复用率 | **4.000**（目标 4.0） |
| 自博弈完成对局 | 491,283 局，1,528.9 万手，378.6 万条样本 |

> 自博弈那一行是三个 actor 的**累计产出**，比 trainer 实际吃进去的 256 万条多 ——
> trainer 到达 `max_steps` 就退出了，而 actor 不知道这件事，还在继续产数据直到被手工停掉。
> 这是编排上的一个真实缺口：`launch_training.sh` 没有"trainer 结束就通知 actor 退出"的机制。

### 一个顺带的确认

样本数 / 手数 = 3,786,397 / 15,289,264 = **24.77%**，和配置里
`full_search_prob: 0.25` 严丝合缝 —— 只有完整搜索的那些手才产出训练目标
（`csrc/selfplay.cpp` 里样本 push 在 `if (slot.full_search)` 里）。

这条值得记，因为我曾经拿附录 A 里的两个数相除得到 58%，据此以为产样率不是 25%。
那两个数来自不同来源、不同时刻（actor 日志 vs trainer 指标，中间隔着 10 次重启
和一个已知的分片记账 bug），**相除没有意义**。这次三个 actor 的日志里手数和样本数
出自同一份统计，才是可信的。

## B.4 棋力标定（零搜索，各 200 局，随机开局 2 子）

| 对手 | 战绩 | 得分率 | Elo 差 | 平均手数 |
|---|---|---|---|---|
| 随机落子 | 200 胜 0 负 0 和 | 100% | +1040 | 10 |
| 贪心威胁基线 | 133 胜 26 负 41 和 | 76.8% | +207 | 70 |
| **renju15**（30,012 步） | **54 胜 146 负 0 和** | **27.0%** | **−173** | 28 |

三场对局里 renju15b 的禁手告负都是 **0 次**。

### 头号指标：零搜索值多少次模拟

零搜索策略对**同权重的 MCTS**，每档 200 局，随机开局 2 子：

| | 各档得分率 | 等效强度 |
|---|---|---|
| **renju15b @ 10,001** | 2→49.2% 4→40.5% 8→30.8% 16→13.5% 32→13.5% | **< 2** |
| renju15 @ 11,662（对照） | 2→48.8% 4→41.9% 8→34.4% 16→14.4% | **< 2** |
| renju15 @ 30,012 | 2→44.8% **4→53.3%** 8→39.3% 16→25.3% | **4 ~ 8** |

**头两行是两次独立训练在相近步数上的结果，每一档都在噪声内吻合**
（49.2 vs 48.8、40.5 vs 41.9、30.8 vs 34.4、13.5 vs 14.4）。

这是这次重跑最有价值的一条：这个指标测量噪声不小（200 局在 p=0.5 处的二项标准差
约 3.5 个百分点），一直很难判断某次读数是真信号还是抖动。现在有了**跨训练的复现**
—— 同一套方案跑到同一步数，曲线重合。说明它测的是方案的稳定性质，不是某一次的偶然。

同时也说明：从约 1 万步到 3 万步，这个指标**确实从 &lt;2 走到了 4~8**。
第 12 章讲的"头号指标不动"针对的是那次学习率衰减实验覆盖的窗口（约 1.5 万~3 万步）
内部的变化，且反复强调了噪声与真实趋势同量级 —— 放在更长的跨度上看，它是会动的，
只是动得比训练侧指标慢得多。

## B.5 两次训练的正面对比

| | renju15（30,012 步） | renju15b（10,001 步） |
|---|---|---|
| trainer 墙钟 | 约 9.7 小时（10 次启动） | **4.30 小时**（一次跑完） |
| 超出目标熵 | **+0.427** | +0.861 |
| top1 一致率 | 68.2% | 53.7% |
| 价值准确率 | 79.1% | 78.4% |
| 威胁识别 | **99.4%** | 91.8% |
| 对贪心基线 | **98.2%** | 76.8% |
| 自博弈平均手数 | 48.6 | 31.1 |
| 自博弈禁手告负 | 0.70% | **0.15%** |

**三倍的训练量换来了实打实的棋力差距**：直接对局 146:54，Elo 相差 173
（约等于 1:2.7 的胜负比），而且黑白两侧都稳定落后（renju15b 执黑 100 局只赢 27）。

这一条对第 12 章的否定性结论是个**重要补充**：那一章说的是"训练侧指标持续改善、
而零搜索相对自身 MCTS 的差距不动"，讲的是**搜索能力的蒸馏没有进展**；
但两个模型之间的**绝对棋力**差距是真实的。换句话说 ——
**继续训练确实会变强，只是变强的部分不是"学会前瞻"。**

### 平均手数是个便宜的棋力指标

31.1 手 vs 48.6 手。棋越弱，越容易出现一方连成五而对手根本没挡住，对局就早早结束。
两个模型互相下时只有 28 手 —— renju15 抓 renju15b 的漏洞抓得很快，局面撑不长。
这个数字不需要任何额外测量，自博弈日志里现成，值得当作一个随时能看的粗略信号。

## B.6 黑白失衡：方向反了，原先的解释站不住

| | renju15 | renju15b |
|---|---|---|
| 黑胜 | **73.7%** | 44.2% |
| 白胜 | 23.3% | **55.6%** |
| 和棋 | 3.0% | 0.19% |

附录 A.8 把 renju15 的黑方压倒性优势归因于"连珠自由开局下先手的理论优势"。
**这次跑出了相反的方向，那个解释就不成立了** —— 同样的规则、同样的代码、同样的超参，
只是重跑一次，先手方从 73.7% 掉到 44.2%。

更可能的情况是：两次训练各自陷进了不同的自博弈风格局部解。自博弈的分布完全由模型
自己决定，一旦某一方的某类走法在早期占了上风，它就会自我强化。这类现象在
只跑一次的实验里**完全看不出来**，只能靠重跑发现。

训练早期的失衡比这还夸张得多：step 3,150 时 actor0 的统计是白胜 79%、平均 29 手/局。
当时我判断"数据还太早，不下结论"，跑完全程后回归到 55.6% —— 这个判断是对的，
但也说明**早期自博弈统计不能用来推断方案有没有问题**。

## B.7 这次训练暴露的两个工程缺口

1. **actor 不知道 trainer 已经结束**。trainer 到达 `max_steps` 退出后，三个 actor
   继续满负荷跑了很久才被手工停掉，白烧三张卡。`launch_training.sh` 的 `stop`
   是纯手动的，缺一个"训练完成即收摊"的信号。
2. **`min_positions_to_start` 仍是绝对值**（附录 A.7 里那个坑）。这次没有触发 ——
   因为全程一次跑完，没有重启。缺口还在，只是没被踩到。

## B.8 权重已删除

`runs/renju15b` 已整个清理，**没有可以拿来对战的权重了**。

保留下来的同类模型是 `runs/renju15`（30,012 步）。多模型对比玩法照旧：

```bash
gomoku-instinct serve --ckpt runs/renju15c --ckpt runs/renju15 --port 8000
```

`--ckpt` 可以给多次，页面上就能切换，而且**用哪个模型是每局各自的事** ——
开两个标签页，拿同一个局面让两个版本分别走，差距是能直接看出来的。
